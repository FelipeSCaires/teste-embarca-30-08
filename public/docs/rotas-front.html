Documentação de Rotas — Front-end

API de usuários (Rails 8 + Devise 5 + PostgreSQL) · Base URL em desenvolvimento: http://localhost:3000

Como a autenticação funciona: a API usa cookie de sessão do Devise. Faça login em POST /users/sign_in (ou cadastre-se em POST /users) e envie o cookie recebido em todas as chamadas seguintes. No navegador, use fetch(url, { credentials: "same-origin" }); no curl, use -c cookies.txt para salvar e -b cookies.txt para enviar.
Atenção:
  • O front precisa ser same-origin (mesma origem do backend). Não há CORS configurado — chamadas de outro domínio/porta com cookies não funcionarão.
  • Envie sempre os cabeçalhos Content-Type: application/json e Accept: application/json. Sem o Accept correto, as rotas do Devise respondem no fluxo HTML (redirects) em vez de JSON.

1. Autenticação (Devise)

MétodoRotaDescriçãoSucessoErro
POST /users Cadastro (sign up). Já autentica e devolve o cookie de sessão. 201 + usuário 422 (validação)
POST /users/sign_in Login. Devolve o cookie de sessão. 201 + usuário 401 (credenciais inválidas)
DELETE /users/sign_out Logout (encerra a sessão). 204 (sem corpo) 401 (ninguém logado)

Cadastro — POST /users

Corpo da requisição (o campo password_confirmation deve ser igual a password; senha mínima de 6 caracteres):

curl -c cookies.txt -X POST http://localhost:3000/users \
  -H "Content-Type: application/json" \
  -H "Accept: application/json" \
  -d '{
    "user": {
      "name": "Fulano da Silva",
      "email": "fulano@example.com",
      "password": "senha123",
      "password_confirmation": "senha123"
    }
  }'

Resposta 201 Created:

{
  "id": 1,
  "email": "fulano@example.com",
  "name": "Fulano da Silva",
  "created_at": "2026-07-30T12:00:00.000Z",
  "updated_at": "2026-07-30T12:00:00.000Z"
}

Resposta 422 Unprocessable Content (exemplo — e-mail já usado):

{
  "errors": {
    "email": ["has already been taken"],
    "password_confirmation": ["doesn't match Password"]
  }
}

Login — POST /users/sign_in

curl -c cookies.txt -X POST http://localhost:3000/users/sign_in \
  -H "Content-Type: application/json" \
  -H "Accept: application/json" \
  -d '{ "user": { "email": "fulano@example.com", "password": "senha123" } }'

Sucesso: 201 + JSON do usuário (e cookie de sessão gravado em cookies.txt).

Falha: 401 com corpo:

{ "error": "Invalid Email or password." }

Logout — DELETE /users/sign_out

curl -b cookies.txt -X DELETE http://localhost:3000/users/sign_out \
  -H "Accept: application/json" -i

Sucesso: 204 No Content. O cookie de sessão deixa de valer.

Rotas auxiliares (fluxo HTML e conta própria)

MétodoRotaDescrição
GET/users/sign_upFormulário HTML de cadastro.
GET/users/sign_inFormulário HTML de login.
GET/users/editFormulário HTML para editar a própria conta.
PATCH/usersAtualiza a própria conta do usuário logado (exige current_password).
DELETE/usersExclui a própria conta do usuário logado.
POST/users/passwordEnvia e-mail de recuperação de senha.
GET/users/password/editFormulário de redefinição de senha (via token do e-mail).
Não confunda: DELETE /users (Devise) exclui a conta do usuário logado; DELETE /api/users/:id (CRUD) exclui qualquer usuário pelo id. Para o front de gerenciamento, use sempre as rotas /api/users.

2. CRUD de Usuários — /api/users

Todas as rotas abaixo exigem sessão autenticada. Sem cookie válido a resposta é 401 com corpo {"error":"You need to sign in or sign up before continuing."}.

Formato do usuário retornado em todas as respostas:

{
  "id": 1,
  "name": "Fulano da Silva",
  "email": "fulano@example.com",
  "created_at": "2026-07-30T12:00:00.000Z",
  "updated_at": "2026-07-30T12:00:00.000Z"
}
MétodoRotaDescriçãoCódigos
GET /api/users Lista todos os usuários (ordenados por id). 200 · 401
GET /api/users/:id Detalha um usuário. 200 · 401 · 404
POST /api/users Cria um usuário. Body: {"user":{name,email,password,password_confirmation}}. 201 · 400 · 401 · 422
PATCH /api/users/:id Atualiza um usuário. Senha em branco/ausente é ignorada (edite só nome/e-mail sem reenviar senha). 200 · 400 · 401 · 404 · 422
DELETE /api/users/:id Exclui um usuário. 204 · 401 · 404

Exemplos

Listar — GET /api/users → 200:

curl -b cookies.txt http://localhost:3000/api/users

Criar — POST /api/users → 201 (ou 422 com erros de validação; ou 400 se faltar a chave user):

curl -b cookies.txt -X POST http://localhost:3000/api/users \
  -H "Content-Type: application/json" \
  -d '{
    "user": {
      "name": "Beltrano",
      "email": "beltrano@example.com",
      "password": "senha123",
      "password_confirmation": "senha123"
    }
  }'

Resposta 422 (exemplo):

{ "errors": { "email": ["can't be blank"], "password": ["can't be blank"] } }

Atualizar — PATCH /api/users/:id → 200 (senha omitida = mantém a atual):

curl -b cookies.txt -X PATCH http://localhost:3000/api/users/2 \
  -H "Content-Type: application/json" \
  -d '{ "user": { "name": "Beltrano Editado", "email": "beltrano@example.com" } }'

Excluir — DELETE /api/users/:id → 204:

curl -b cookies.txt -X DELETE http://localhost:3000/api/users/2 -i

Resposta 404 (id inexistente):

{ "error": "Registro nao encontrado" }
Se você excluir o próprio usuário logado via DELETE /api/users/:id, a sessão deixa de ser válida nas próximas requisições (novo login necessário).

3. Telas de gerenciamento (HTML) — /admin/users

Além da API JSON, o app tem telas HTML prontas para gerenciar usuários. Após um login válido (/users/sign_in) ou cadastro (/users/sign_up), o usuário é redirecionado automaticamente para a página que tentou acessar originalmente (quando houver) ou para /admin/users (tela de lista). Acessar qualquer rota /admin/* sem sessão redireciona para o formulário de login.

MétodoRotaDescrição
GET/admin/usersLista de usuários com ações de editar/excluir e logout.
GET/admin/users/newFormulário de criação de usuário.
POST/admin/usersCria o usuário e volta para a lista.
GET/admin/users/:id/editFormulário de edição (senha em branco = mantém a atual).
PATCH/admin/users/:idAtualiza o usuário e volta para a lista.
DELETE/admin/users/:idExclui o usuário (com confirmação). O usuário da sessão atual não pode se excluir por esta tela.
Essas telas usam o fluxo HTML padrão (formulários com token CSRF embutido) — não precisam de cabeçalhos especiais. A API JSON /api/users continua disponível para front separado.

4. Fluxo completo (curl)

# 1. Cadastrar (ja loga e salva o cookie)
curl -s -c cookies.txt -X POST http://localhost:3000/users \
  -H "Content-Type: application/json" -H "Accept: application/json" \
  -d '{"user":{"name":"Fulano","email":"fulano@example.com","password":"senha123","password_confirmation":"senha123"}}'

# 2. Listar usuarios (autenticado)
curl -s -b cookies.txt http://localhost:3000/api/users

# 3. Criar outro usuario
curl -s -b cookies.txt -X POST http://localhost:3000/api/users \
  -H "Content-Type: application/json" \
  -d '{"user":{"name":"Beltrano","email":"beltrano@example.com","password":"senha123","password_confirmation":"senha123"}}'

# 4. Atualizar (senha omitida = inalterada)
curl -s -b cookies.txt -X PATCH http://localhost:3000/api/users/2 \
  -H "Content-Type: application/json" \
  -d '{"user":{"name":"Beltrano Editado","email":"beltrano@example.com"}}'

# 5. Excluir
curl -s -b cookies.txt -X DELETE http://localhost:3000/api/users/2 -i

# 6. Logout
curl -s -b cookies.txt -X DELETE http://localhost:3000/users/sign_out \
  -H "Accept: application/json" -i

5. Resumo de códigos de status

CódigoSignificadoQuando ocorre
200OKListagem, detalhe e atualização com sucesso.
201CreatedCadastro, login e criação de usuário com sucesso.
204No ContentLogout e exclusão com sucesso (sem corpo).
400Bad RequestCorpo sem a chave user.
401UnauthorizedSem sessão válida, ou credenciais de login inválidas.
404Not FoundUsuário com o :id informado não existe.
422Unprocessable ContentFalha de validação (e-mail duplicado, senha curta, confirmação divergente…).
